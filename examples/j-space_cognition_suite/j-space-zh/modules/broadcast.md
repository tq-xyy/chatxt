# 广播枢纽（broadcast）

作用：共享名称、数值、约束、风格锚点只推导一次，所有依赖分支从同一个源头读，禁止各自复制。

依据：一次把 France 换成 China 的干预同时改变了四个问题的答案（首都/大洲/货币/语言）——四个计算读的是同一个实例。重新推导不是勤奋，是当初没写好。

## 协议

### 写一次（多部分任务开始时）

1. 识别共享核心：哪些实体、参数、约束、风格锚点会被多个子任务用到？
2. 每个压缩为规范词或短语。
3. 加载（三步缺一不可）：陈述它 → 陈述使它关键的那一个事实 → 立即使用一次。只是提到不算加载，提到过的东西活不到第四个子任务。
4. 声明活集："接下来所有内容的核心是 <a>、<b>。" 两个是上限，其余进账本。

### 读多次（子任务期间）

- 每个子任务从枢纽读核心，绝不从上下文碎片本地重建——那是两个章节出现两个版本名字的由来。
- 子任务似乎需要不同版本的核心项 = 信号不是便利，在枢纽解决分歧，不在分支里。
- 将要推导某东西前，先问：枢纽里已经有了吗？这一问一行 token，是全任务最便宜的一笔。

### 单点替换（核心变化时）

1. 在枢纽执行一次替换："核心现在是 <新值>。"
2. 审计下游：替换之前写的每个章节都值得怀疑。France→China 双向成立：一次编辑移动所有读枢纽的东西，一个过期的私有副本污染所有不读枢纽的东西。

### 一致性审计（交付前）

1. 重读枢纽集。
2. 逐章节核对：同名、同数、同时态、同立场。
3. 持有分歧副本的章节 = 没读枢纽，从枢纽重写，不要就地打补丁。

## 自检

- 刚才推导出的东西里，有什么是第二次才推出来的？应该在第一次写在哪？
- 声明一个核心条目、说出它的关键事实、并在下一句真的用到它——用到了吗？

## 去往

枢纽超过两个活条目 → capacity；核心条目要活过长的机械段 → directed-focus；某部分完成并验证 → markers。
