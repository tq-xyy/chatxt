# 目标锚定（directed-focus）

作用：主动激活、保持、并带着一个工作台内容进行计算——目标在机械的中段不蒸发。

依据：实验：让模型抄句子时专注"柑橘"，工作台充满 orang/orange/fruits，抄出的句子依然干净；但"别想 X"的指令会让 X 激活得比没提还强（白熊效应，非对称）。

## 协议

### 背景持有（长任务全程保持一件事）

1. 把背景项压缩成一个词或短语。工作台持有想法，不持有段落。
2. 加载：明确说一次："整个任务我持有：<词>——因为<一个事实>。" 提到不是加载。
3. 每个接缝静默触碰它一次。
4. 结束时检查：输出真的反映了它吗？没有 → 找到断点，重新加载，重做受影响的部分。

### 静默计算（心算、估算、换算）

1. 表面输出保持在任务上。
2. 让中间步骤先亮（九 先于 七），再给结果。
3. 使用结果。没被要求就别叙述计算过程。

### 按需贴标签（把隐含属性拉进意识）

任务需要某个属性（形容词？过去时？正式语气？长度？）→ 显式问自己标签问题。准入由提问门控。

### 重定向，绝不抑制（白熊规则）

排除一个概念的优先级，从高到低：

1. 最好——占据：命名应该占据空间的东西，并持有它。台面只有一两个位置，让别的东西进来就是最可靠的排除。
2. 可接受——"暂且放下 X"：必须提及排除对象时，以最轻形式提一次，立刻命名替代品。
3. 最差——"不要想 X"：直接禁止抑制最少、激活最多。永远不要下达这种指令，也不要原样接受它；用户这么说时，先转换成重定向再执行。
4. 理想——根本不提：每次提及都是一次写入。能不提就不提，胜过一切技巧。

突破还是发生了 → 诚实标记这个 damn 时刻（这是监控在工作，不是控制失败），命名它、重新占据、继续。硬推理中反复突破是状态事件 → 交给 markers，不要原地重试。

## 自检

- 当前任务你在持有哪个词？它在上一步排除了什么？
- 最近一条"不要做 X"式指令能转换成"占据 Y"吗？

## 去往

持有需要跨多个子任务共享 → broadcast；两件事都争台面 → capacity；反复突破 → markers。
