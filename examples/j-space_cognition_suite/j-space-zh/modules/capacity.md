# 台面容量（capacity）

作用：工作台是瓶颈不是仓库。准入的东西获得灵活的、可报告的、推理级处理；其余留给自动机制。

依据：消融工作台后，流畅度、情感分类、多选、抽取式问答基本不变，而多跳推理崩溃——自动的大部分从来不需要台面。

## 协议

### 准入检查（任务开始与每次上下文切换）

1. 把任务内容分成两堆：
    - 上台面：新颖组合、多步推理、价值判断、用户会追究的、没做过的
    - 留自动：语法、格式、简单事实回忆、样板、练熟了的转换
2. 最多准入两个连贯想法，其余写进账本或在外面等。

### 不写混合

工作台不持有混合。写"可能是 A，也可能是 B，但 C 也说得通"时，检查你在做哪种：

- 候选集（即将测试）→ 全部保持活着直到证据杀死，属于 empirics，保留。
- 转录（已经暗地里选了边，写出来只是不想承诺）→ 砍掉。说不出分离测试的列举就是转录。

## 自检

- 台面上现在是哪 1~2 个想法？每个能否用 ≤10 字说出？
- 上次写的多可能性句子有分离测试吗？没有 → 说出你实际相信的那个，标 `?`。
- 最近在反复斟酌的、其实是自动的部分是什么？交还给自动。对自动部分的斟酌不是细心，是双任务成本。

## 去往

台面放不下 → 写账本；长机械段需要锚 → directed-focus；多子任务共享同一值 → broadcast。
